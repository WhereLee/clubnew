# 技术管理员实施方案（Tech Admin 落地版）

> 状态：**方案待确认**（确认后按 P0→P2 实施）
> 关联：《技术管理员设计.md》P0 阶段的具体化；本方案不含 agent 观测（P1-P4 留待后期）
> 讨论背景：2026-08 在线调研 + 项目现状盘点后形成

---

## 1. 目标（大白话）

1. 把"技术管理员"从概念变成真实角色：**看得见系统运行状态，但碰不到业务数据**
2. 把已有的监控资产（Prometheus 指标、操作/登录日志、业务计数器）**装进一个页面**，不用再翻 Grafana 猜该看哪
3. 保持"系统管理员管业务、技术管理员管运行"的职责分离（企业实践）

---

## 2. 调研结论（2026-08，star 为 GitHub 实测）

企业监控体系分四层，成熟度三级：

| 层 | 作用 | 典型工具（2026） |
|---|---|---|
| 指标 Metrics | 看数字（QPS/延迟/内存） | **Prometheus**(66k★) + **Grafana**(76k★) |
| 日志 Logs | 看文字（出事翻记录） | ELK / **Loki**(29k★，与 Grafana 同厂，轻量) |
| 链路 Tracing | 看过程（一次请求每站耗时） | SkyWalking(25k★) / OpenTelemetry |
| 告警 Alerting | 看时机（超阈值主动喊人） | Alertmanager / 钉钉 webhook |

成熟度：青铜=只有日志 → 白银=指标+日志+看板 → 黄金=+链路+告警。
**本项目目标 = 白银**（单体规模，链路/告警评估后不引入，理由见 §7）。

## 3. 现状盘点（项目已有 vs 缺什么）

| 资产 | 现状 | 缺什么 |
|---|---|---|
| Prometheus + Grafana | ✅ compose 已配，actuator 暴露指标 | 没有面向"运维人员"的页面导航 |
| 业务计数器 | ✅ 报名/签到/限流等已有 | 审批/AI 工具/登录失败等 3 个补充 |
| 操作日志 sys_oper_log | ✅ @Log 注解 + AOP，61 处写操作全覆盖 | 登出/注册两个盲区（无注解） |
| 登录日志 sys_login_log | ✅ 成功/失败都记（含失败原因） | 无需改动 |
| AI 工具日志 agent_tool_log | ✅ 全工具调用记录 | 无需改动（trace 留待后期） |
| 角色体系 | ✅ RBAC 三角色 | 缺 tech_admin 角色 + 监控菜单 |

**结论：底座全在，本方案 = "分钥匙 + 装导航 + 补三个计数器 + 补两个日志盲区"。**

## 4. 方案设计

### 4.1 角色分离（发两把钥匙）

```
系统管理员 admin  → 系统管理（用户/角色/菜单/字典/参数）+ 业务审批（社团/经费）
技术管理员 tech_admin → 监控中心（运行概览 + 操作日志 + 登录日志）+ Grafana 入口
```

- **互斥不互兼**：登录后按角色渲染菜单；接口层双重校验（菜单权限 + 角色）
- 技术管理员**无任何业务写接口权限**（"能看不能碰"）

### 4.2 监控中心三页面（admin-web 新增分区）

| 页面 | 内容（大白话） | 数据源 |
|---|---|---|
| **运行概览** | 一屏看系统：JVM 内存/GC、请求 QPS、P95 延迟、今日错误数、业务计数器（审批/AI 工具/登录失败） | 后端 `/monitor/overview` 接口直接读**应用内存中的 Micrometer MeterRegistry**（本机零外部依赖，Prometheus 为云服务器平行采集通道，同源同值） |
| **操作日志** | 谁/何时/干了什么/成功失败（可筛操作人、业务类型、状态） | sys_oper_log 表（已有 CRUD，迁权限） |
| **登录日志** | 登录成功/失败记录（失败原因、IP；可筛状态） | sys_login_log 表（已有 CRUD，迁权限） |

- 概览页数字来源：micrometer 已采集的 `jvm_*`、`http_server_requests_*`、`custom_*` 指标 → 后端查询 Prometheus HTTP API（`/api/v1/query`）→ 前端卡片 + 趋势图
- 保留「查看 Grafana」外链（深度分析跳 Grafana，日常看概览页）

### 4.3 日志盲区补齐（审计完整性）

- `AuthController.logout` 加 `@Log(title = "登录管理", businessType = 3)`（登出留痕）
- `AuthController.register` 加 `@Log(title = "注册管理", businessType = 1)`（注册留痕）
- 理由：登录有登录日志，登出/注册无痕是审计洞；一行注解的事

### 4.4 业务计数器补充（3 个）

| 计数器 | 埋点位置 | 用途 |
|---|---|---|
| `club_audit_total`（社团审批数，按结果分） | ClubController 审批接口 | 业务活跃度 |
| `agent_tool_total`（AI 工具调用 成功/失败/拒绝） | AbstractAgentTool 执行处 | AI 健康度（拒绝率=安全面信号） |
| `login_failed_total`（登录失败次数） | LoginServiceImpl.recordLoginLog(status=失败) | 安全（撞库检测） |

已有计数器（报名/签到/限流）不动。

### 4.5 权限与数据变更（文件级）

| 类型 | 变更 |
|---|---|
| 迁移脚本 V4 | `sys_role` 插入 tech_admin（role_key='tech_admin', data_scope='1'）；`sys_menu` 插入监控中心目录 + 3 页面 + 1 按钮权限；`sys_role_menu` 关联 |
| 后端 | `SysMenuController/SysUserController` 的 `@PreAuthorize` 权限串沿用现有 `system:*` + 新增 `monitor:*` 权限串；日志查询接口权限从 `system:operlog:list` 迁移为 `monitor:operlog:list`（兼容旧 admin 角色：admin 保留 system:*，tech_admin 只有 monitor:*） |
| 接口 | 新增 `MonitorController`（/monitor/overview 聚合指标）；日志查询复用现有 SysOperLog/SysLoginLog controller（仅权限串调整） |
| 前端 | admin-web：`router` 加监控中心路由（tech_admin 菜单渲染）；`views/monitor/` 三页面；`api/monitor.ts` |

## 5. 实施计划（P0→P2）

| 阶段 | 任务 | 文件/范围 | 工作量 |
|---|---|---|---|
| **P0 角色与权限** | ① V4 迁移（角色/菜单/关联） ② 权限串调整（monitor:*） ③ 日志接口权限迁移 | db/migration/V4、SysOperLog/SysLoginLog controller、SecurityConfig 无需改（走现有 @PreAuthorize） | 0.5 天 |
| **P0 日志补盲** | ④ logout/register 加 @Log | AuthController | 0.1 天 |
| **P1 概览页** | ⑤ MonitorController（聚合 Prometheus 查询） ⑥ 前端运行概览页（卡片+趋势） ⑦ 前端 api/monitor.ts | 后端 1 controller + 前端 1 页面 | 1 天 |
| **P1 计数器** | ⑧ 3 个业务计数器埋点（审批/AI 工具/登录失败） | ClubController、AbstractAgentTool、LoginServiceImpl | 0.2 天 |
| **P2 收尾** | ⑨ Grafana 入口 + 标准仪表盘 JSON（JVM/HTTP/业务三块） ⑩ 测试：权限断言（tech_admin 可见/不可见）+ 全量 mvn test + 前端 build | compose 或 docs 提供 JSON、测试类 | 0.5 天 |

**总计 ≈ 2.5 天**（可并行项：④⑧ 独立）。

## 6. 验收标准

1. `tech_admin` 账号登录 admin-web → 侧边栏只有「监控中心」分区，三个页面有真实数据
2. `admin` 账号登录 → 看不到监控中心；tech_admin 无任何业务接口权限（HTTP 403 验证）
3. 运行概览页数字与 Grafana 同源一致（同一 Prometheus）
4. 登出/注册后 sys_oper_log 有记录；登录失败后 sys_login_log + `login_failed_total` 计数器同时增长
5. `mvn test` 全绿（含新增权限断言测试）+ 双前端 build 通过 + CI 三 job 全绿

## 7. 明确不做（防止做飘）

| 不做 | 理由（面试可讲） |
|---|---|
| 链路追踪 SkyWalking/OTel | 单体单进程，无跨服务调用；"我评估过不需要，等拆分微服务再引入" |
| 告警（Alertmanager/钉钉） | 白银级先行；"下一步规划"而非现状 |
| 日志采集链路 ELK/Loki 文件采集 | 日志已落库可查，文件级采集对单体是负担 |
| agent 观测（trace/prompt 治理） | 已规划《技术管理员设计.md》P2-P4，本次不混入 |

## 8. 面试叙事（这轮做完能讲什么）

- **职责分离**："业务管理员与技术管理员分离，对应企业 SRE 与业务系统的边界；互斥不互兼防监守自盗"
- **白银级可观测性**："单体项目的监控落地：指标（Prometheus）+ 日志（审计表）+ 看板（概览页），并说明为什么不做链路/告警——不是不会，是规模评估后的取舍"
- **日志设计**："写操作全记（@Log 注解 + AOP）、读操作不记（防日志风暴）、登录成功失败分记（安全信号）"
- **业务计数器**："给业务装里程表：审批数、AI 工具拒绝率（安全信号）、登录失败数（撞库信号）"
